## 1. `qne/` core library

### HIGH
| # | Finding | Fix |
|---|---|---|
| C1 | **Key material was regenerable from the scenario file.** `ScenarioConfig.seed` defaulted to 42 and seeded Alice's bits/bases, Bob's bases and the QBER sample. | **FIXED**: `seed` defaults to `None` (OS entropy); `derived_seed()` helper; `reproducible` flag; test `test_unseeded_runs_produce_different_keys`. Seeded runs remain available for cross-validation and are documented as *not secret*. |
| C2 | **Efficient (biased-basis) BB84 kept X–X bits in the key** (`qne/bob.py`) while rating with 1−h(e_z)−h(e_x), which only covers Z–Z key bits. The `qne-sequence` path was already correct. | **FIXED**: all X–X matches disclosed, key = Z–Z minus the Z sample; test `test_biased_bases_key_is_z_only_and_all_x_disclosed`. |
| C3 | **No error verification after Cascade.** An even-weight residual error survived silently with `reconciled: true`; `finite_key.py` charged log2(2/ε_cor) for a hash that was never exchanged. | **FIXED** (shared `qne/reconcile.py`, so both paths): Bob sends a seeded Toeplitz (2-universal) tag of `t = ceil(log2(2/ε_cor))` bits in `RECONCILE_DONE`; Alice answers `RECONCILE_VERIFY`; mismatch raises `KeyVerificationError` on both sides and no key is output. Asymptotic mode subtracts `t` from the PA length; finite mode already pays for it. Callers in `qne/` and `qne-sequence/` handle the error; `node_runner` reports `verification_failed`. Test `test_residual_error_is_caught_by_verification`. |
| C4 | **Finite-key accounting was unreachable on the raw-socket path** (no CLI flag; `drive_cascade` always asymptotic). | **FIXED**: `qfabric bob --finite-key --eps-sec --eps-cor`; `Bob(finite_key=...)`. |

### MEDIUM
| # | Finding | Fix |
|---|---|---|
| C5 | Statistical-fluctuation constant did not match the cited TLGR paper: code used √((n+k)(k+1)/(2nk²)·ln(1/ε_PE)); TLGR Eq. (2) is √((n+k)/(nk)·(k+1)/k·ln(4/ε_sec)) — code was ~√2 smaller (unsafe direction relative to the citation). Verified against arXiv:1103.4130v2 Eq. (2). | **FIXED** to the published constant; pinned test `test_serfling_mu_matches_tlgr_constant`. Consequence: a 6 k-pulse block now (correctly) yields zero finite-key bits; two distributed tests adjusted to assert that both sides agree on zero rather than on a positive key. |
| C6 | Dark counts fired only in slots where a frame arrived; lost photons never dark-counted (under-reports QBER exactly where darks dominate; disagreed with the NetSquid adapter and `distributed_qkd`, which do model empty slots). | **FIXED** in `qne/bob.py`: after the receive loop every unseen slot gets a dark-count draw. |
| C7 | `detection_window` not configurable (fixed 1 ns), so `dark_count_rate` was effectively uncalibratable. | **FIXED**: `DetectorConfig.detection_window` (YAML + `to_dict`). |
| C8 | Unbounded frame read from an unauthenticated 4-byte length prefix; server `accept()`/data sockets had no timeouts. | **FIXED**: `MAX_FRAME_BYTES = 64 MiB` → `ProtocolError`; `ClassicalServer(accept_timeout, data_timeout)`; `--accept-timeout`. |
| C9 | Bare `assert` on network-supplied message types (vanish under `python -O`). | **FIXED**: explicit `ProtocolError`. |
| C10 | `--auth-key` on the command line (visible in `ps`, deploy logs). | **FIXED**: `--auth-key-file` and `$QNE_AUTH_KEY` take precedence. |
| C11 | Decoy detection model added dark counts: 1−(1−η)^n + p_dc (can exceed 1). | **FIXED**: 1−(1−p_dc)(1−η)^n and gain 1−(1−p_dc)e^{−ημ}. |
| C12 | `loss_threshold_u32` could reach 2³² (overflows the P4 `bit<32>` to 0 = lossless). | **FIXED**: clamp to 2³²−1. |
| C13 | Key rate uses the point-estimate QBER in asymptotic mode (Wilson CI computed but unused). | Accepted as the definition of the asymptotic mode; finite-key mode (now reachable) is the defensible number. Documented. |
| C14 | `bits_to_int` drops leading zeros / returns None for empty. | Documented as a comparison token only. |

   waits on a receive), so they need **no coordinator and no grants** — a shared
   per-node `LogicalClock` is the whole mechanism, and one clock per *node* (not per
   link) because a station serving two links is a single sequential entity. Slice
   evidence: E91 over raw L2 certified (220/221 frames checked, 0 late, CHSH 2.742)
